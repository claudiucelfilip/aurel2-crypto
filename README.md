# aurel2-crypto

Systematic crypto trading system. Two independent strategies running 24/7 against Binance:

- **Momentum** — weekly rebalance into the strongest of {BTC, ETH, SOL, AVAX, LINK} over a 28-day lookback. 10% trailing stop-loss. Daily absolute-momentum filter exits to USDT when all coins are negative.
- **Funding carry** — opens cash-and-carry positions (long spot + short perp) when 8h funding rates exceed the entry threshold. Live mode only — Binance demo API is spot-only.
- **Idle USDT yield** — Flexible Earn subscribes idle USDT cash between trades (live mode only).

## Layout

- `src/aurel2_crypto/live/daemon.py` — 24/7 trading daemon. Polls every 5 min, writes heartbeat every 60s.
- `src/aurel2_crypto/dashboard/app.py` — FastAPI dashboard at `:8081`.
- `src/aurel2_crypto/strategies/` — momentum + funding carry signal logic.
- `src/aurel2_crypto/broker/binance.py` — ccxt-based Binance broker (spot + perps).
- `scripts/backtest_*.py` — historical backtests (one per strategy variant explored).
- `docker/` — production deploy via `docker compose`.

## Running

Local dev:
```bash
uv pip install -e .[dev,dashboard]
aurel2-crypto live --paper          # demo/testnet daemon
aurel2-crypto dashboard --port 8081 # dashboard
```

Production (this machine):
```bash
bash scripts/deploy.sh   # rsyncs to /opt/aurel2-crypto and rebuilds containers
```

## Dashboard

`http://localhost:8081/`

- **Status row** — daemon heartbeat, current momentum holding (with trailing-stop floor), exchange connection.
- **Live Run** — equity curve of the active testnet/demo (or live) run.
  - Stats: starting / current / all-time P&L / window return / peak / drawdown.
  - Period selector (`1D` / `1W` / `1M` / `6M` / `1Y` / `5Y` / `ALL`) — only periods with meaningfully distinct data are shown given the actual run length. A young run (e.g. 6 days) hides the longer options to avoid showing identical lines.
  - Chart auto-refreshes every 60s along with the rest of the page.
- **Backtest performance** — historical equity curve from `data/chart_data.json` (generated by `scripts/generate_chart_data.py`), shown alongside BTC buy-and-hold.
- **Recent activity** — last 50 trades from the journal.

### Equity tracking

The daemon writes three files under `~/.aurel2-crypto/`:

| File | Purpose |
|---|---|
| `heartbeat.json` | Per-minute snapshot: connection state, holding, HWM, current equity. |
| `equity_curve.json` | Time series of equity snapshots (15-min interval, capped at 40k points). Source for the live chart. |
| `run_state.json` | Run anchor — `started_at` + `starting_equity`. Initialized on first equity snapshot. |
| `trade_journal.json` | Append-only log of every order action with reasoning. |

`run_state.json` can be edited (or deleted to re-anchor) if the run's true starting equity needs correcting — the demo testnet run was backfilled this way using historical hourly ETH prices.

## API

- `GET /api/status` — daemon heartbeat
- `GET /api/trades?limit=N` — recent trade journal entries
- `GET /api/chart` — backtest chart data
- `GET /api/live-progress?period=1d|1w|1m|6m|1y|5y|all` — live run equity curve + stats
